1. Pipeline Alur Kompilasi (End-to-End)

Architecture

Setiap berkas kode sumber .dap dianalisis, diverifikasi, dioptimalkan, dan ditranslasikan melalui 6 tahap berurutan sebelum dieksekusi oleh salah satu dari 3 backend kompilasi.

📝

1. Lexer & Tokenizer

src/lexer/mod.rs • src/lexer/token.rs

Membaca aliran karakter UTF-8 mentah, melacak nomor baris/kolom via SourceMap di src/span.rs, memetakan kata kunci bahasa Indonesia (fungsi, jika, kembali, struktur), serta mengenali operator modern seperti Walrus (:=) dan Error Union (!).

🌲

2. Pratt Parser & AST Construction

src/parser/mod.rs • src/ast/mod.rs

Membangun Abstract Syntax Tree (AST) bebas titik koma menggunakan kombinasi Recursive Descent untuk pernyataan dan Pratt Precedence Climbing untuk ekspresi biner/uner. Dilengkapi pemulihan kesalahan (error recovery) agar dapat mendeteksi beberapa sintaks keliru sekaligus.

⚖️

3. Hindley-Milner Type Inference

src/types/mod.rs

Melakukan analisis tipe statis penuh tanpa keharusan mengetik tipe manual di setiap variabel. Menjamin keamanan tipe, memvalidasi kepatuhan sifat (traits), mendeteksi kegagalan pada T ! E (Error Union), dan menolak nilai null/nil secara matematis.

⚡

4. Comptime Evaluator

src/comptime/mod.rs

Mengevaluasi blok fungsi beranotasi comptime sebelum fase eksekusi runtime. Menghasilkan konstanta, tabel lookup, atau ekspresi tereduksi untuk komputasi instan berbobot zero runtime overhead.

🛡️

5. Perceus & Ownership Drop Analysis

src/ownership/mod.rs

Menganalisis grafik aliran kontrol (*control-flow graph*). Menentukan peminjaman referensi (& dan &mut) dan secara otomatis menyisipkan instruksi pelepasan memori (drop) tepat pada titik penggunaan terakhir (*last-use*), serta mendeteksi pemakaian ulang buffer (*in-place mutation*).

⚙️

6. IR Lowering & Backend Target Emission

src/ir/mod.rs

Menyusun instruksi ke format Representasi Perantara (IR) berbasis blok dasar (Basic Blocks). Dari sini, IR disalurkan ke salah satu dari tiga backend berikut:

🏃 Runtime Interpreter

src/eval/mod.rs
Eksekusi instan langsung tanpa waktu tunggu kompilasi biner. Mendukung coroutine jalan_paralel & tunggu.

⚡ Ahead-of-Time C11

src/codegen/mod.rs
Transpilasi ke standar C11 + runtime Perceus native. Dikompilasi via GCC/Clang ke biner mandiri .exe.

🌐 WebAssembly Wasm32

src/wasm/mod.rs
Generator biner Wasm32 mandiri tanpa dependensi LLVM. Menghasilkan berkas .wasm siap browser.

📱 Mobile PWA & Android

src/mobile/mod.rs
Bundler Progressive Web App & template Android Studio/Gradle. Dilengkapi QR Code Wi-Fi untuk uji coba di ponsel.

3. Sistem Tipe & Error Union (T ! E)

Hindley-Milner

DapCode memadukan inferensi tipe kuat tanpa titik koma. Kesalahan runtime tidak diperlakukan sebagai exception yang tak terduga, melainkan dimodelkan sebagai tipe aljabar Error Union.

Konsep Inti: Tipe bulat ! teks berarti ekspresi tersebut mengembalikan nilai bulat jika sukses, ATAU mengembalikan nilai teks jika gagal. Operator tanda seru (!) memisahkan kondisi sukses di sisi kiri dan kondisi error di sisi kanan.
Definisi Tipe di src/types/mod.rs 
pub enum Type {
    Int,                               // bulat / u64
    Float,                             // desimal / f64
    String,                            // teks / Teks
    Bool,                              // bool / Bool
    Unit,                              // unit / Unit
    List(Box<Type>),                   // Daftar<T>
    Map(Box<Type>, Box<Type>),         // Kamus<K, V>
    ErrorUnion(Box<Type>, Box<Type>),  // T ! E
    Struct(String, Vec<(String, Type)>),
    Trait(String, Vec<TraitMethod>),
    Function(Vec<Type>, Box<Type>),
    Var(usize),                        // Variabel inferensi H-M
}

4. Manajemen Memori Deterministik Perceus

Zero-GC Safe

Modul src/ownership/mod.rs menerapkan analisis kepemilikan kompilasi berbasis affine-types yang terinspirasi oleh teori Perceus Reference Counting (digunakan juga oleh Koka dan Lean 4).

Karakteristik Garbage Collection (GC) Tradisional DapCode (Perceus & Auto-Ownership)
Waktu Pelepasan Tertunda (stop-the-world pause) Deterministik (tepat pada titik last-use variabel)
Beban Runtime Besar (background thread scanner) Nol (instruksi drop disisipkan statis saat kompilasi)
Peminjaman (Borrowing) Tidak ada konsep pinjam (semua pointer) Otomatis diinferensi (referensi & / &mut)
Reuse Buffer Objek baru dialokasikan ulang di heap In-place mutation jika refcount bernilai 1

🎯 Target 1: Runtime Tree-Walk Interpreter & Konkurensi

src/eval/

Backend interpreter DapCode mengeksekusi pohon sintaksis abstrak (AST) dan IR secara langsung tanpa waktu tunggu kompilasi biner. Sangat ideal untuk pengembangan cepat, REPL interaktif, dan lingkungan scripting dinamis.

Eksekusi Instan: Jalankan berkas kode sumber langsung dari terminal menggunakan perintah dapcodec run program.dap atau buka konsol interaktif melalui dapcodec repl.

🧠 Struktur Nilai Dinamis (eval::Value)

Mengelola nilai runtime fleksibel: integer Int(u64), desimal Float(f64), string String(String), boolean Bool(bool), koleksi dinamis List & Map, instansiasi Struct, serta handler tugas asynchronous Task(TaskId).

🌳 Lexical Environment Berantai

Menangani cakupan variabel bertingkat (*lexical scoping*) menggunakan pointer referensi ke cakupan induk (*parent environment*), memastikan isolasi variabel lokal dalam fungsi, percabangan, dan blok loop.

⚡ Colorless Coroutine (jalan_paralel)

Konkurensi modern tanpa fungsi berwarna (*function coloring*). Blok jalan_paralel { ... } meluncurkan tugas asynchronously ke thread pool runtime, dan disinkronkan kembali menggunakan tunggu.

Contoh Konkurensi & Eksekusi di Interpreter (src/eval/mod.rs) 
/// Contoh kode DapCode konkurensi mandiri
fungsi ambil_data(id: u64) -> teks {
    // Simulasi operasi I/O jaringan
    kembali "Data pengguna #{id}"
}

fungsi utama() {
    // Meluncurkan tugas coroutine di thread pool background
    tugas1 := jalan_paralel { ambil_data(101) }
    tugas2 := jalan_paralel { ambil_data(102) }

    // Menunggu hasil kedua tugas secara deterministik
    hasil1 := tunggu tugas1
    hasil2 := tunggu tugas2

    cetak("Hasil 1: {hasil1}")
    cetak("Hasil 2: {hasil2}")
}

⚡ Target 2: Ahead-Of-Time (AOT) C11 Transpiler & Native Engine

src/codegen/

Backend AOT mentranspilasikan AST dan IR DapCode ke kode sumber C11 ISO murni berkecepatan tinggi, yang kemudian dikompilasi menggunakan compiler native sistem (GCC, Clang, atau MSVC) menjadi file biner mesin mandiri (.exe di Windows, ELF di Linux, Mach-O di macOS).

Komponen Codegen Peran & Implementasi di src/codegen/
Runtime C Tersemat (c_runtime.h) Menyediakan pustaka runtime C minimalis dengan alokasi memori Perceus ref-counted untuk DapString, DapList, DapMap, dan error union propagation.
Otomasi Toolchain Native Secara cerdas mendeteksi keberadaan GCC (MinGW), Clang, atau Microsoft Visual C++ (cl.exe) di PATH sistem, lalu mengompilasi kode C dengan optimasi -O2 / /O2.
Zero External Dependencies Biner hasil kompilasi adalah aplikasi native mandiri tanpa memerlukan instalasi interpreter, virtual machine, atau runtime tambahan di komputer target.
Perintah Kompilasi Biner Native C11 
# Kompilasi langsung menjadi biner berekstensi .exe (Windows)
dapcodec build program.dap -o program.exe

# Kompilasi dan emit kode sumber C11 mentah untuk diinspeksi
dapcodec build program.dap --emit-c program.c

# Jalankan biner native hasil kompilasi
./program.exe

🌐 Target 3: Pure Rust Standalone WebAssembly (Wasm32)

src/wasm/

Generator WebAssembly mandiri 100% Rust tanpa dependensi LLVM atau Emscripten. Menghasilkan modul biner WebAssembly standar (.wasm) yang ringan, cepat, dan siap dijalankan langsung di peramban web modern, Node.js, atau runtime Wasmtime/Wasmer.

📦 Arsitektur Seksi Biner Wasm32 (LEB128 Binary Emitter)
Binary Spec
Seksi 1: Type Section
Mendeklarasikan tanda tangan fungsi (parameter & hasil).
Seksi 2: Import Section
Fungsi interop host: konsol print, canvas draw, waktu.
Seksi 3: Function Section
Memetakan indeks fungsi ke tanda tangan tipe.
Seksi 7: Export Section
Mengekspor fungsi titik masuk utama ke JavaScript.
Seksi 10: Code Section
Opcode bytecode Wasm32 (i32.add, call, loop, br_if).
Kompilasi WebAssembly & Pemuatan via JavaScript 
# 1. Kompilasi program DapCode ke berkas .wasm murni
dapcodec wasm program.dap -o program.wasm

// 2. Instansiasi dan jalankan di browser atau Node.js
const response = await fetch('program.wasm');
const bytes = await response.arrayBuffer();
const { instance } = await WebAssembly.instantiate(bytes, {
    env: {
        dap_cetak: (ptr, len) => { /* Host I/O Print */ }
    }
});
instance.exports.utama();

src/mobile/

🤖 Template Android Studio (Gradle)

5. Panduan Praktis Pengembang (How-To Guides)

Actionable

Langkah-langkah terperinci bagi kontributor untuk memodifikasi atau memperluas fitur kompilator.

1

Menambahkan Sintaksis atau Kata Kunci Baru

Contoh: Menambahkan kata kunci perulangan ulangi N { ... }:

📦 Ekosistem Pustaka Standar Tersemat (Batteries Included)

stdlib

DapCode menyediakan pustaka standar bawaan (*batteries included*) berkecepatan tinggi yang terintegrasi langsung di dalam runtime tanpa memerlukan pustaka pihak ketiga.

src/db/ (Database ACID) Key-Value Engine

Engine database Key-Value tersemat dengan transaksi atomik (mulai_transaksi, komit, batal), Write-Ahead Logging (WAL) untuk ketahanan crash, pencarian awalan (*prefix scan*), dan ekspor JSON.

src/net/ (HTTP & WebSocket) RFC 6455 & REST

Server jaringan mikroservis mandiri: router rute dinamis dengan parameter jalur (/api/produk/:id), penanganan CORS otomatis, serta implementasi penuh jabat tangan dan frame WebSocket.

src/regex/ (Reguler Ekspresi) Zero-Dependency NFA

Mesin pencocokan pola regex berbasis NFA backtracker mandiri: karakter sembarang (.), kuantifier greedy (*, +, ?, {n,m}), grup penangkap (...), dan kelas karakter (\d, \w, \s).

src/time/ (Kalender & Waktu) Civil Calendar

Penghitungan waktu presisi tinggi berbasis algoritma Howard Hinnant untuk kalender sipil: penentuan tahun kabisat, hari dalam seminggu, format standar ISO 8601, serta pemformatan tanggal kustom.

src/crypto/ (Kriptografi) FIPS 180-4 & Base64

Fasilitas keamanan kriptografi standar: fungsi hashing SHA-256 (FIPS 180-4), hashing MD5 (RFC 1321), serta encoder/dekoder teks dan biner Base64 (RFC 4648).

src/json/ (Parser & Serializer) Recursive Descent

Pengurai JSON mandiri berkecepatan tinggi yang memetakan objek JSON langsung ke tipe data aljabar DapCode (Daftar, Kamus, angka, teks) serta serialisasi objek kembali ke teks JSON.

🛠️ Ekosistem Perkakas: LSP Server & DAP Debugger

tooling

DapCode dilengkapi perkakas pengembangan modern berstandar industri: Language Server Protocol (LSP) untuk intelijensi editor, Debug Adapter Protocol (DAP) untuk inspeksi breakpoint grafis, dan pemformat kode bawaan.

💡 Language Server Protocol (src/lsp/)

Dijalankan melalui dapcodec lsp via protokol JSON-RPC standar stdio: diagnosa galat real-time saat mengetik, autocompletion nama fungsi dan kata kunci, hover docs lengkap, serta navigasi Go To Definition.

🐞 Debug Adapter & CLI Debugger (src/debug/)

Server DAP untuk antarmuka debug grafis di VS Code serta konsol interaktif terminal (dapcodec debug berkas.dap) dengan titik henti (b), langkah demi langkah (n, s), inspeksi variabel (p), dan continue (c).

✨ Formatter & Doc Generator (src/fmt/ & src/doc/)

Memformat kode sumber secara seragam dan konsisten (dapcodec fmt), mode CI/CD (dapcodec fmt --check), serta generator dokumentasi HTML interaktif dari komentar doc-comments (dapcodec doc).

Perintah CLI Tooling Pengembang 
# 1. Jalankan LSP Server di latar belakang (digunakan oleh ekstensi editor)
dapcodec lsp

# 2. Buka sesi debugger interaktif terminal dengan breakpoint
dapcodec debug program.dap
(dap-debug) b 14          # Pasang breakpoint di baris 14
(dap-debug) c             # Lanjutkan eksekusi hingga breakpoint
(dap-debug) p nama        # Cetak nilai variabel 'nama'
(dap-debug) n             # Langkah ke baris berikutnya

# 3. Format seluruh berkas kode sumber di proyek
dapcodec fmt src/

📦 Manajer Paket dappkg & Sistem Modul Multi-Berkas

src/modules/

Modul src/modules/mod.rs menyediakan sistem pemuatan modul terisolasi, resolusi jalur kanonikal, serta manajer paket resmi dappkg untuk tata kelola proyek berskala besar.

Fitur Manajer Paket Deskripsi & Mekanisme Penanganan
Pemuatan Modul Kanonikal Sintaksis impor "nama_modul" atau impor "jalur/ke/modul.dap". Pemuat mendeteksi dependensi melingkar (*circular dependency cycle*) secara dini sebelum analisis tipe dilakukan.
Manifes DapCode.toml Mendefinisikan metadata paket: nama paket, versi SemVer, berkas titik masuk utama (berkas_utama = "src/utama.dap"), dan daftar pustaka dependensi.
Kunci Hash DapCode.lock Mengunci versi paket dan hash SHA-256 integritas konten untuk menjamin hasil kompilasi yang deterministik dan identik (*reproducible builds*).
Mode Vendor Mandiri Perintah dappkg vendor mendownload seluruh pustaka ke direktori lokal vendor/ agar proyek dapat dikompilasi secara offline tanpa koneksi internet.
Contoh Berkas Manifes DapCode.toml 
[paket]
nama = "aplikasi_pelanggan"
versi = "1.0.0"
penulis = ["Daffa <daffa@dapcode.id>"]
berkas_utama = "src/utama.dap"

[dependensi]
dap_http = "0.4.0"
dap_kripto = "0.2.1"
